## 一、原始需求（用户原话）

> "做一个 mcp 用于 AI 帮助抓取浏览器的进程，抓取和获取网页的开发者人员工具中的内容，并且支持一键保存，后续我会放 GitHub 开源"

拆解成三件事：
1. **抓取浏览器进程** —— 枚举本机正在运行的浏览器进程，识别哪些可以被附加
2. **获取开发者工具内容** —— console 日志、网络请求、DOM、性能指标、storage、截图等
3. **一键保存** —— 把抓到的东西批量落盘成可归档、可分享的产物

最终形态：一个 MCP Server，AI 客户端（Claude Desktop / Cursor / WorkBuddy 等）通过它操作浏览器。

## 五、关键设计决策与已知坑（踩过的，别改回去）

1. **Chrome 111+ 必须加 `--remote-allow-origins=*`**，否则 WebSocket 握手被直接拒绝（已在 `launch.ts` 里）
2. **`--remote-debugging-pipe` 的浏览器无法用 TCP 端口附加**，只能提示改用 `browser_launch`
3. **Windows 枚举进程必须用 PowerShell CIM**（`wmic` 已弃用）；`ConvertTo-Json` 单结果时返回对象而非数组，`process.ts` 的 `parseJson` 已兜底
4. **Firefox 不走 CDP**，标注为"不可附加"（`family: firefox`）
5. **子进程过滤**：命令行带 `--type=renderer|gpu|utility` 的是子进程，默认过滤掉，只保留浏览器主进程
6. **时间口径**：wall clock 用 `Date.now()` 记时间戳；请求耗时用 CDP 事件 timestamp 差值计算（这个才准，CDP 的时间是 monotonic 不是 epoch）
7. **flatten session**：一个 browser 级 WebSocket 通过 `Target.attachToTarget({flatten:true})` 多路复用所有标签页，不要每页开一条连接
