## 项目：browser-devtools-mcp
- **状态：已完成、可运行，实时订阅 + 多浏览器验证通过**（2026-09-27 收尾）。34 个 MCP 工具，`typecheck` / `build` 全绿；**Chrome 与 Edge 双浏览器端到端均通过**，Edge 另有有头模式专项验收（`npm run acceptance:edge`）。一键保存产出 13 类文件，实时录制产出 JSONL + 帧图 + 统计。
- **支持的浏览器**：Chrome / Edge / Brave / Vivaldi / Opera / Chromium，`browser_launch({ kind })` 或 `executable` 指定；Edge 与 Chrome 协议等价。`target_list` 会默认折叠自带扩展页等后台目标（有头 Edge 上这类目标可达十几个）。
- 目标：MCP server，让 AI 通过 CDP 抓取浏览器进程 + 开发者工具内容（console / network / DOM / 性能指标 / storage），**支持实时事件订阅**，支持一键保存；用户后续要开源到 GitHub。
- 位置：`D:/项目/浏览器抓取mcp/`（2026-09-27 由 `C:/Users/Administrator/WorkBuddy/2026-09-26-22-41-17/browser-devtools-mcp/` 迁入，原目录已删除）
- 技术栈（已定）：TypeScript + Node（ESM, Node16 module resolution, strict）；依赖 @modelcontextprotocol/sdk / ws / zod；不引 express。
- 连接策略（已定）：优先附加已有浏览器（扫描 9222–9235 端口的 /json/version），没有则启动带 `--remote-debugging-port` 的独立实例，user-data-dir 用临时目录。
- 传输：stdio 为主，另提供 `--transport http`。
- **实时层（三层，别打乱）**：产出（store 的事件总线 + session 的 7 类通道）→ 分发（`src/live/manager.ts` 订阅/过滤/缓冲/游标/长轮询/合并推送）→ 消费（`src/tools/live.ts` + `src/live/recorder.ts` 落盘）。
- 实时设计原则：**缓冲优先于推送**。客户端不支持通知也没关系，事件先进订阅缓冲，再由 `events_wait` 拉取，永不丢量；推送失败自动降级 `push:'none'` 不报错。
- 一键保存产物：session.json / console.json / network.har / network.csv / dom.html / screenshot.png / metrics.json / storage.json / report.html / summary.md / manifest.json。

## 关键坑（改代码前先看 PROGRESS.md 第 5 节）
- CDP target 字段是 `targetId` 不是 `id`，凡处理 target 必须走 `normalizeTarget()`。
- `DOM.getDocument` 返回的是 document 节点（nodeType 9），不是元素节点。
- Windows 删 Chrome profile 极慢，只允许 detached 子进程后台删，不要同步阻塞工具调用。
- 新版 Chrome 的 ResourceType 首字母大写（`Script`/`Document`/`Fetch`），比较时忽略大小写。
- Chrome 111+ 必须 `--remote-allow-origins=*`；debugging-pipe 无法 TCP 附加；Firefox 不走 CDP。
- 耗时只能用 CDP timestamp 差值算（monotonic），wall clock 用 `Date.now()`。
- MCP 发实时通知走 `server.notification()`；用标准 `notifications/message` 需在 capabilities 声明 `logging: {}`，自定义 method（`notifications/browser-devtools/events`）无需声明。
- **`Browser.getVersion`（CDP 命令）返回 camelCase**（`product`/`protocolVersion`/`userAgent`），与 HTTP 端点 `/json/version` 的 PascalCase（`Browser`/`Protocol-Version`）不同。写代码别混用，版本一律从 product 串解析。
- 页面在附加之前已加载完时抓不到它的历史网络请求，这是协议行为不是 bug；要抓网络就必须在附加之后再导航。
- 测试里不要用 favicon 制造 404（有头 / headless 行为不一致），显式 `fetch('/xxx-404')` 才稳定。
- 没订阅时不要白采样：订阅增删都会走 `syncFeatures()`，自动启停 Performance 定时采样与 screencast 推流。
