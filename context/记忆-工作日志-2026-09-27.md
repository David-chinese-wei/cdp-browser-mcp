## 本次踩到并已修复的坑（重要）

1. **CDP target 字段是 `targetId` 不是 `id`**（新版 Chrome）。原接口写成 `id`，导致所有目标塞进同一个 `undefined` 键互相覆盖，表现形式是"浏览器起来了但没有附加到页面"。已加 `normalizeTarget()` 统一收口，`Target.getTargets` 和 `Target.targetInfoChanged` 都要过它——后者漏改会出现"URL 更新了但标题不更新"。
2. **`DOM.getDocument` 返回 document 节点（nodeType 9）而非元素**，旧 `buildOutline` 直接 return，大纲恒为空。
3. **Windows `rmSync` 删 Chrome profile 耗时 40+ 秒**（几万小文件 + Defender），会卡到 MCP 请求超时。改为 detached 子进程后台删除，工具立即返回。
4. 新版 Chrome ResourceType 首字母大写（`Script`/`Document`/`Fetch`），旧版小写；过滤逻辑已大小写不敏感。
5. headless 启动后首 tab 可能是 `chrome://newtab/`，需轮询等待真实页面。

## browser-devtools-mcp：新增实时获取（同一天续做）

需求：一次性抓取之外，要能实时拿到正在发生的事。按「产出 → 分发 → 消费」三层实现：

- `src/capture/store.ts` 加实时事件总线：全局递增 cursor + 事件环形缓冲（默认 5000 条）+ `onEvent/emit/eventsSince/dropOlderThan`。
- `src/capture/session.ts` 产出 7 类通道事件（console / network / error / navigation / target / metric / frame）；新增 `Page.startScreencast` 实时推帧、`Performance.getMetrics` 定时采样、`watchAllTargets` 给所有标签页（含之后新开的）自动挂域。
- `src/live/manager.ts` 订阅管理器：通道/关键字/级别/标签页过滤 + 每订阅缓冲 + 游标续接 + `events_wait` 长轮询 + 40ms 合并推送；`src/live/recorder.ts` 实时落盘 JSONL + 帧图片。
- `src/tools/live.ts` 7 个实时工具：`events_subscribe / wait / read / unsubscribe / list`、`recording_start / stop`；`server.ts` 里做推送接线。工具总数 27 → 34。
- 已验证：typecheck / build / smoke 全绿；对 https://example.com 实跑录制，1 秒内 165 条事件、3 帧画面正常落盘。

### 本轮新坑
1. MCP SDK 发通知用 **`server.notification()`**（`sendNotification` 不是 Server 的公开方法）；自定义 method 的能力断言走 default 分支不报错，但 `notifications/message` 必须在 capabilities 声明 `logging: {}`。
2. `LiveManager` 内 `unsubscribe` 既做私有字段又做方法名 → 外部调用报 TS2721，字段改名 `detachListener`。
3. 长轮询唤醒必须按「waiter 游标之后的条数」判断，不能用 `buffer.length`：否则第二次 wait 起会被缓冲区残留的旧数据顶回来，退化成忙轮询。
4. 画面帧很占空间：事件环额外 `dropOlderThan('frame', 12)` 只留最近几帧，读取时默认不带 base64。
5. 冒烟断言实时事件必须**循环长轮询累计**，只做一次 wait 会误判漏事件。

### 修掉的 bug（都是静默错数据，类型检查抓不到）
1. **`Browser.getVersion`（CDP 命令）返回 camelCase**：`product` / `protocolVersion` / `userAgent`；代码却按 HTTP 端点 `/json/version` 的 PascalCase `Browser` / `Protocol-Version` 取值 → `meta.browser` 恒为 `'Chromium'`、`browserVersion` 恒空。现在两者兼容，`meta` 新增 `browserUserAgent` / `protocolVersion`。**教训：同一个"版本号"在 CDP 命令和 HTTP 端点里字段名不同。**
2. `hub.connect` 把 `protocolVersion` 塞进 `browserVersion`，且 session 用 `??` 会被外部传值短路；改为版本一律由 product 串解析（`Edg/140.0.3485.54` → `140.0.3485.54`）。
3. `summary.md` 写 `(protocol ${browserVersion})`——标签与值都对不上。改 `产品串（CDP x.y）`。
4. **`target_list` 淹没**：有头 Edge 13 个目标里 9 个是自带扩展页 / service worker / offscreen 文档。改为默认折叠后台目标、返回 `type`、加 `includeBackground` 开关，并保护「过滤到空则回退全量」。

### 写测试脚本自己踩的坑
- `--browser` 解析：找不到参数时 `find` 返回 `''`，`indexOf('')` = -1，取到 `process.argv[0]`（node 路径）。用 `findIndex` 判 -1。
- 页面在附加前已加载完时 `network_list` 必然为空——**这是正确行为**，测试要重新导航才验得到网络采集。
- 别用 favicon 制造 404：有头/headless 行为不一致。显式 `fetch('/xxx-404')`。
- `page_screenshot` 默认不回传 base64，断言 `shot.data` 必失败。
